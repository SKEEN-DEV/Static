Post-Phase 6 — Bug Fixes

Fixes June 11, 2026

Bug 1 — DataBarChart: only one bar rendered on vertical layout

Root Cause

The DataBarChart component conditionally rendered XAxis / YAxis wrapped in <>...</> fragments. Recharts 1.8.5 uses React.Children traversal internally to register axis components by type — it does not look inside fragments. When layout="vertical" (horizontal bars), the XAxis type="number" and YAxis type="category" were never registered, so Recharts fell back to default axis types and all bars stacked at Y-position 0, appearing as a single bar.

The PillarDistribution chart was unaffected because its default layout="horizontal" happens to match Recharts' fallback axis defaults.

Fix

Replaced the fragment-wrapped conditional with separate inline conditionals so each axis is a direct child of BarChart:

DataBarChart.tsx
{isHorizontal ? (
    <XAxis type="number" tick={tickStyle} />
) : (
    <XAxis dataKey={categoryDataKey} ... />
)}
{isHorizontal ? (
    <YAxis type="category" ... />
) : (
    <YAxis tick={tickStyle} />
)}

Bug 2 — AiViewNarrative: NaN rendered in paragraph

Root Cause

AiViewNarrative.tsx referenced brand.positiveCount, brand.negativeCount and brand.neutralCount. These fields do not exist on BrandMetric — the interface only exposes a composite sentimentScore (0–1). Adding undefined + undefined + undefined produced NaN, which React rendered as an empty <strong> and logged a console warning.

Fix

Replaced the broken sentiment breakdown with brand.sentimentScore * 100. The narrative now reads: "With a sentiment score of X%, the brand appears in Y% of top-3 responses…" Removed the now-unused safePct import.

Bug 3 — Recharts 1.8.5: false prop-type warnings in console

Root Cause

Recharts 1.8.5 ships with malformed propTypes validator definitions on Tooltip (allowEscapeViewBox.x) and Line (points[0].value). The validators are undefined instead of valid PropTypes functions, so React logs "invalid prop type" warnings on every fresh session.

The original code hit the same bug but warnings never surfaced because React only fires each prop-type warning once per browser session — other charts elsewhere in the app had already consumed the warning budget before the AI View tab was opened. The new isolated wrapper files render these Recharts components independently and earlier, causing them to appear first.

Fix

Cleared the broken propTypes objects at import time in both chart wrapper files. Dev-only metadata — no effect on rendering or production builds:

TrendLineChart.tsx & DataBarChart.tsx
// Recharts 1.8.5 ships with invalid propType
// validator definitions. Clearing them removes
// false dev warnings with no runtime impact.
(Tooltip as any).propTypes = undefined;
(Line as any).propTypes = undefined;

Coding Standards Applied

TypeScript / React

  • export const Comp = (props: Props) => { pattern throughout
  • No explicit return type annotations where inferable
  • Props destructured inside the function body
  • JSDoc with @interface, per-prop /** */, @example on hooks
  • Path aliases: @luminaUtils/*, @luminaHooks/*, @luminaComponents/*, @luminaScss/*

SCSS Modules

  • .__className camelCase naming convention
  • @use "~@luminaScss/Settings/index" as settings;
  • @use "~@luminaScss/LuminaSettings.scss" as luminaSettings;
  • @use "~@luminaScss/Tools/index" as tools;
  • No hardcoded hex values — luminaSettings colour variables throughout
  • Spacing via settings.$spacing-unit-*
  • Typography via ai-font mixin
