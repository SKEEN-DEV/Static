Executive Summary

The AI View panel is a 954-line monolithic component that analyzes and visualizes AI-generated industry rankings. It processes complex data structures, calculates multiple metrics, and renders interactive charts and statistics across three tabs. While functionally complete, it violates Lumina coding standards by mixing data processing, business logic, and presentation in a single file.

Key Issues
  • ❌ All logic in one massive component file (954 lines)
  • ❌ No reusable sub-components extracted
  • ❌ Direct Recharts usage instead of Lumina chart wrappers
  • ❌ Inline styles mixed with SCSS modules
  • ❌ Complex data processing (~200 lines) embedded in component
  • ❌ No separation of concerns
  • ❌ Violates centralized Lumina-App patterns (Hooks/, Utilities/, Interfaces/)
Proposed Solution
  • ✅ Extract to 33 files (3 hooks, 3 utilities, 2 chart wrappers, 25 components)
  • ✅ Use centralized Lumina-App folders (Hooks/, Utilities/, Interfaces/)
  • ✅ Create reusable Recharts wrappers in /Components/UI/Charts/ (benefits 3 files)
  • ✅ Organize AI View components in /Components/AiView/ with /Tabs/ subfolder
  • ✅ Reduce main component to ~150 lines (orchestrator only)
  • ✅ 6-day effort (5 development + 1 testing/docs)
Refactoring Complexity: High (6 days total - 5 development + 1 testing/docs)

3.3 Key Algorithms

1. Sentiment Mapping

Converts text sentiment to numeric score

SENTIMENT_MAP = {
  "very positive": 2,
  "positive": 1,
  "neutral/mixed": 0,
  "negative": -1,
  "very negative": -2
}
2. Authority Weighting

Different content types have different trust scores

AUTHORITY_MAP = {
  "news": 1.0,
  "academic sources": 0.95,
  "reports": 0.9,
  "social media": 0.25,
  // ... 15 more types
}
3. Freshness Decay

Recent content weighted higher

freshnessWeight(monthsOld) {
  if (monthsOld < 1) return 1.0;
  if (monthsOld < 6) return 0.75;
  if (monthsOld < 12) return 0.5;
  return 0.2;
}
4. Composite AI View Score

Weighted combination of 5 factors

score = (
  visibility × 0.2 +    // 20%
  authority × 0.2 +     // 20%
  freshness × 0.15 +    // 15%
  sentiment × 0.25 +    // 25%
  dominance × 0.2       // 20%
) × 100

5.3 Final Component Structure

After refactoring, the main component should be ~150 lines (down from 954 lines) with 3 custom hooks and 6 imported components.

// /Components/Panels/AiView.tsx (~150 lines)

import { useAiViewData, useAiViewMetrics, useAiViewFilters } from '@luminaHooks';
import { 
    LuminaAiViewHeader, 
    LuminaAiViewTabs,
    LuminaCompetitorTab,
    LuminaPositionTab,
    LuminaSourcesTab,
    LuminaEmptyState
} from '@luminaComponents/AiView';

const LuminaAiView = () => {
    // 1. Data fetching (custom hook)
    const { aiViews, selectedAiViewId, ... } = useAiViewData();
    
    // 2. Metrics computation (custom hook)
    const { runMetrics, latestRun, previousRun } = useAiViewMetrics(allRuns);
    
    // 3. Filter state (custom hook)
    const { activeTab, setActiveTab, ... } = useAiViewFilters();
    
    // 4. Pure composition - render tabs
    return (
        <div>
            <LuminaAiViewHeader .../>
            <LuminaAiViewTabs .../>
            {activeTab === "competitor" && <LuminaCompetitorTab .../>}
            {activeTab === "position" && <LuminaPositionTab .../>}
            {activeTab === "sources" && <LuminaSourcesTab .../>}
        </div>
    );
};
Key Features:
  • ✅ 150 lines (down from 954)
  • ✅ No business logic - only composition
  • ✅ 3 custom hooks for data/metrics/filters
  • ✅ Clean separation of concerns

9. Key Takeaways

What Makes AI View Different
  1. Data Complexity: Most complex data processing in any Lumina panel
  2. Chart Variety: Only panel with multiple chart types (LineChart, BarChart vertical/horizontal, CSS donut)
  3. Tab Structure: Only panel with 3 distinct tabs (Competitor, Position, Sources)
  4. Metrics Calculation: Unique scoring algorithm with 5 factors (visibility, authority, freshness, sentiment, dominance)
  5. Recharts Dependency: One of only 3 components using Recharts library
Why It Needs Refactoring
  1. Maintainability: 954-line file is hard to understand and modify
  2. Reusability: Should use existing LuminaViewToggleButton component instead of custom buttons
  3. Testing: Current structure makes unit testing nearly impossible
  4. Standards: Violates Lumina coding patterns (no sub-components, no extracted hooks)
  5. Performance: Potential optimization opportunities with memoization
  6. Chart Inconsistency: Direct Recharts usage instead of Lumina wrappers
Architectural Decisions Made
  1. Centralized Hooks/Utilities: Use /Lumina-App/Hooks/ and /Lumina-App/Utilities/ instead of creating local duplicates
  2. Centralized Interfaces: Add to existing /Lumina-App/Interfaces/interfaces.ts instead of separate file
  3. Chart Wrappers in /UI/Charts/: Create TrendLineChart and DataBarChart for app-wide Recharts usage
  4. Purpose-Based Chart Naming: Avoid collision with existing /Infographics/LuminaLineChart (custom SVG)
  5. Tab Subfolder: Organize tab orchestrators in /Components/AiView/Tabs/ for clarity
  6. Reusability Evaluation: Keep AI View-specific components (TopicCloud, ScoreDonut) in /Components/AiView/ rather than /UI/
Benefits After Refactoring
  1. Clarity: Each component has single responsibility (60-150 lines each)
  2. Testability: Can test utilities, hooks, and components independently
  3. Reusability: Chart wrappers benefit 3 components across app (AiView, ContactArticlesGraph, Circulation)
  4. Maintainability: Changes isolated to specific components
  5. Standards Compliance: Matches patterns in Summary, Contacts, Digest panels
  6. Future-Proof: Easier to add new tabs, metrics, or charts
  7. Centralized Patterns: Leverages existing Lumina-App infrastructure
