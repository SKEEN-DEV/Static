Chart Palettes

Two 10-colour palettes for brand-agnostic rotation across chart series (lines, bars, donut slices, competitor sets). Each has a paired strong variant with matched hues at higher chroma — use it where the pastel base washes out (large text, dense word clouds, filled badges).

Set 1 — Calm (pastel) Active default

Brand-flavoured pastel, low-chroma. Best for dense charts — many lines, stacked bars, small legends — where colour differentiates but shouldn't dominate. First four entries drive the Reputation Pillars.

Set 2 — Bold (brand-highlights led) Alt / not active

Set 2 isn't currently switched on in the app — Set 1 wins by default because its pastel tones sit back and let dense charts breathe. Set 2 is here as a ready-to-swap alternative: change ACTIVE_PALETTE_SET in Config/chartPalettes.ts from Set1 to Set2 and every chart across Lumina restyles at once — including the Reputation Pillars, since they're pulled from the first four entries of whichever set is active.

Reach for it (or use getPalette('bold') on a per-chart basis) when brand recognition should lead the visual — hero cards, single-KPI donuts, topic clouds, marketing screenshots — anywhere the identity colours should read as the point rather than neutral background chrome. The trade-off is loudness: put ten Set 2 series on one chart and they start to fight, which is exactly why the calmer Set 1 is the default for dense multi-series work.

How to use

Import CHART_PALETTE for the active base or CHART_PALETTE_STRONG for the matched strong variant. Use toStrongChartColor(hex) to look up the strong sibling of a base colour, or getPalette('bold') to request a specific kind regardless of the app-wide default.

Semantic — brand qualities

Reputation Pillars

Colours for the four Reputation Pillars — Direction, Performance, Integrity, Innovation. Sourced from the first four entries of the active chart palette, so pillar visuals restyle in lockstep when the base palette is swapped.

Semantic — diverging

Sentiment Palette

Meaning-carrying diverging ramp for sentiment buckets. Deliberately not sourced from CHART_PALETTE — green means positive, red means negative, grey means neutral / unknown, and that mapping must stay stable when the chart palette is swapped.

Semantic — sequential

Source Age Ramp

Sequential mint → navy ramp for citation-age buckets, ordered fresh to stale. Kept separate from Sentiment because age is descriptive, not evaluative — an old source isn't a "bad" source, just an older one.

Semantic — brand identity

AI Model Palette

Identity colours for AI model providers, matched to each vendor's own brand where possible. Resolved via substring matching against the model identifier (specific product names win over generic vendor names) with a fallback to the rotating chart palette when no hint applies.

Legacy theme · Pulsar

Pulsar Palette

Pulsar is the pre-Lumina theme that still powers the classic MCD chart surfaces and Pulsar-branded widgets. Lumina's new charts don't use it, but shared components (chart legends, channel pills, sentiment badges on legacy views) still resolve against these tokens. Sourced from Assets/Scss/Settings/_Settings.Colors.scss ($pulsar-palette).

Core brand tones Identity

The identity hues Pulsar leans on across headers, primary actions and callouts. Higher-chroma than Lumina's tokens — this is a system built to look bright on white chrome rather than to blend into a gradient background.

Chart series Rotating

Eleven rotating series colours used by legacy Pulsar charts (chart-color-1 through chart-color-11). Deliberately punchier and less brand-tied than Lumina's Set 1 — Pulsar charts sit inside a white card, not on a themed surface.

Channel colours Semantic

Semantic channel identifiers reused across Pulsar filters, chips and stacked-bar segments. These mappings are stable across the app — online is always ochre, social is always navy — so users can read a channel breakdown without checking the legend.

Structural neutrals Chrome

The greys that carry Pulsar's chrome — text, dividers, panel surfaces, disabled states. Each has a matching -light-* ramp in the SCSS for tints and shades; only the anchor tones are shown here.
